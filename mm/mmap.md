SECTION 0: WHAT THIS FILE IS (VERY IMPORTANT)
================================================================================

This is the **CORE of Linux user virtual memory management**

It handles:

    ✔ mmap()        → create mapping
    ✔ munmap()      → destroy mapping
    ✔ brk()         → heap growth
    ✔ VMA management (split, merge, insert)
    ✔ address space allocation
    ✔ overcommit policy
    ✔ stack growth
    ✔ interaction with page tables (indirect)

--------------------------------------------------------------------------------
ONE LINE:
--------------------------------------------------------------------------------

    mmap.c = "VMA MANAGER + ADDRESS SPACE ALLOCATOR"


================================================================================
SECTION 1: CORE DATA STRUCTURES
================================================================================

Process memory:

    mm_struct
        |
        +-- mmap (linked list of VMAs)
        +-- mm_rb (RB-tree of VMAs)
        +-- mmap_cache (fast lookup)
        +-- total_vm
        +-- locked_vm


VMA:

    vm_area_struct
        |
        +-- vm_start
        +-- vm_end
        +-- vm_flags
        +-- vm_file (NULL = anonymous)
        +-- vm_pgoff
        +-- anon_vma


--------------------------------------------------------------------------------
ASCII:
--------------------------------------------------------------------------------

Virtual Address Space:

    0x0000 ----------------------------------------> TASK_SIZE

    [ code ]
    [ heap ]
    [ mmap regions ]
    [ stack ]


VMA list:

    [VMA1] -> [VMA2] -> [VMA3]


RB-tree (for fast lookup):

              VMA2
             /    \
          VMA1    VMA3


================================================================================
SECTION 2: mmap() ENTRY → do_mmap_pgoff()
================================================================================

This is THE most important function.


--------------------------------------------------------------------------------
FLOW:
--------------------------------------------------------------------------------

do_mmap_pgoff(file, addr, len, prot, flags, pgoff):

    1. validate input
    2. align len
    3. find free address (get_unmapped_area)
    4. compute vm_flags
    5. check permissions
    6. check overcommit
    7. try vma_merge()
    8. allocate new VMA
    9. call file->mmap() OR setup anon
   10. insert VMA into structures
   11. update accounting
   12. optionally pre-fault (MAP_POPULATE)

================================================================================
SECTION 14: FILE vs ANONYMOUS MAPPING
================================================================================

FILE MAPPING:

    vma->vm_file != NULL
    uses file->mmap()


ANONYMOUS:

    vma->vm_file = NULL
    uses anon_vma


--------------------------------------------------------------------------------
ASCII:
--------------------------------------------------------------------------------

File-backed:

    VA → page cache → disk


Anonymous:

    VA → anonymous page → swap

================================================================================
SECTION 17: CRITICAL INSIGHTS (INTERVIEW GOLD)
================================================================================

1) mmap creates VMA, NOT pages

2) Actual memory allocated on:
        → page fault

3) VMA stored in:
        → linked list + RB-tree

4) Merging reduces fragmentation

5) Overcommit allows "fake allocation"

6) munmap must:
        → split + remove + free
