===============================================================================
x86_64 FPU / SSE STATE HANDLING
File: arch/x86_64/kernel/i387.c
===============================================================================

PURPOSE
=======

This file manages floating-point/SSE state for each task.

It handles:

    - FPU initialization
    - SSE/FXSAVE support
    - MXCSR feature mask
    - lazy FPU state saving
    - signal frame FPU save
    - ptrace FPU access
    - core dump FPU state


===============================================================================
BACKGROUND: WHAT IS i387?
===============================================================================

Historically, x86 floating-point hardware was called the 80387/i387.

In modern x86_64 this also includes:

    - x87 FPU registers
    - MMX state
    - SSE/XMM registers
    - MXCSR control/status register


So "i387.c" really means:

    floating-point and SIMD register state handling


===============================================================================
WHY FPU STATE NEEDS SPECIAL HANDLING
===============================================================================

Each process has its own CPU register state.

Normal registers:

    RAX RBX RCX RDX ...

are saved during context switch.

But FPU/SSE state is large:

    x87 registers
    XMM registers
    MXCSR
    control words

Saving/restoring it on every context switch is expensive.

So Linux uses lazy FPU handling.


===============================================================================
FPU STATE PER TASK
===============================================================================

Each task has:

    task_struct
        |
        v
    thread.i387.fxsave


This stores FPU/SSE state in FXSAVE format.


Diagram:

task_struct
    |
    +--> thread
           |
           +--> i387
                  |
                  +--> fxsave


===============================================================================
FXSAVE
======

FXSAVE is an x86 instruction.

It saves:

    x87 FPU state
    MMX state
    XMM registers
    MXCSR

into a memory area.


FXRSTOR restores it later.


Important:

    FXSAVE area must be 16-byte aligned.


This file checks:

    offsetof(task_struct.thread.i387.fxsave) & 15

If misaligned:

    __bad_fxsave_alignment()


===============================================================================
MXCSR
=====

MXCSR is the SSE control/status register.

It controls things like:

    - floating-point exception masks
    - rounding mode
    - flush-to-zero
    - denormals-are-zero


Not all MXCSR bits are supported on every CPU.

So Linux calculates:

    mxcsr_feature_mask


This tells which MXCSR bits are legal.


===============================================================================
mxcsr_feature_mask_init()
===============================================================================

Purpose:

    Discover valid MXCSR bits.


Flow:

mxcsr_feature_mask_init()
      |
      +--> clts()
      |
      +--> zero current fxsave area
      |
      +--> fxsave current state
      |
      +--> read mxcsr_mask from fxsave image
      |
      +--> if CPU reports zero, use default mask
      |
      +--> mxcsr_feature_mask &= mask
      |
      +--> stts()


clts()
------

Clear TS bit in CR0.

Meaning:

    allow FPU instructions


stts()
------

Set TS bit in CR0.

Meaning:

    next FPU use traps with #NM


Why?

The kernel temporarily uses FXSAVE, then restores lazy-FPU trap behavior.


===============================================================================
CR0.TS AND LAZY FPU
===============================================================================

CR0.TS = Task Switched bit.

If TS=1 and task executes FPU/SSE instruction:

    CPU raises #NM

#NM = Device Not Available exception


Linux uses this to lazily initialize/restore FPU state.


Flow:

Task scheduled in
      |
      v
CR0.TS = 1
      |
      v
Task executes SSE instruction
      |
      v
#NM exception
      |
      v
math_state_restore()
      |
      v
restore/init FPU state
      |
      v
continue task


===============================================================================
fpu_init()
===============================================================================

Purpose:

    Initialize FPU/SSE support on CPU boot.


Flow:

fpu_init()
      |
      +--> check FXSAVE alignment
      |
      +--> enable CR4.OSFXSR
      |
      +--> enable CR4.OSXMMEXCPT
      |
      +--> clear CR0.TS and CR0.EM
      |
      +--> initialize MXCSR feature mask
      |
      +--> clear thread status
      |
      +--> clear used_math flag


CR4.OSFXSR
----------

Enables FXSAVE/FXRSTOR and SSE support.


CR4.OSXMMEXCPT
--------------

Enables unmasked SSE exception support.


CR0.EM
------

Emulation bit.

If set, FPU instructions trap for software emulation.

Linux clears it because real FPU/SSE exists.


CR0.TS
------

Task switched bit.

Cleared temporarily so FPU can be initialized.


===============================================================================
init_fpu()
===============================================================================

Function:

    init_fpu(struct task_struct *child)


Purpose:

    Initialize FPU state for a task if it has not used math yet.


Flow:

init_fpu(child)
      |
      +--> has task already used math?
      |        |
      |        +--> yes:
      |              |
      |              +--> if current, save live FPU state
      |              +--> return
      |
      +--> zero fxsave area
      |
      +--> set x87 control word = 0x37f
      |
      +--> set MXCSR = 0x1f80
      |
      +--> mark child used math


Default values:

    cwd   = 0x37f
    mxcsr = 0x1f80


These are standard initial FPU/SSE control states.


===============================================================================
USED_MATH FLAG
===============================================================================

Linux tracks whether a task has used FPU.

If task never used FPU:

    no need to save/restore FPU state

If task used FPU:

    task->thread.i387.fxsave is meaningful


Functions/macros:

    used_math()
    clear_used_math()
    tsk_used_math()
    set_stopped_child_used_math()


===============================================================================
save_i387()
===============================================================================

Purpose:

    Save FPU state into user signal frame.


Used during signal delivery.

When a signal is delivered, user context must include FPU state so that
sigreturn can restore it later.


Flow:

save_i387(buf)
      |
      +--> if task never used math
      |        |
      |        +--> return 0
      |
      +--> clear used_math
      |
      +--> is FPU state currently live in CPU?
      |        |
      |        +--> yes:
      |              |
      |              +--> FXSAVE directly to user buffer
      |              +--> stts()
      |
      +--> else:
      |        |
      |        +--> copy saved fxsave image to user buffer
      |
      +--> return 1


===============================================================================
WHY CLEAR used_math() IN save_i387()
===============================================================================

Code:

    clear_used_math(); /* trigger finit */


Meaning:

    After signal frame saves FPU state, Linux wants future FPU use to
    reinitialize/restore state through the lazy FPU path.


===============================================================================
LIVE FPU STATE VS SAVED FPU STATE
===============================================================================

Case 1: FPU state live in CPU

    TS_USEDFPU set

    CPU registers contain current FPU state.

Need:

    FXSAVE from CPU into user signal frame.


Case 2: FPU state already saved in task_struct

    TS_USEDFPU not set

Need:

    copy task->thread.i387.fxsave to user buffer.


Diagram:

Live case:

    CPU FPU registers
          |
          v
    user signal frame


Saved case:

    task_struct.thread.i387.fxsave
          |
          v
    user signal frame


===============================================================================
get_fpregs()
===============================================================================

Purpose:

    ptrace reads task FPU registers.


Used by debuggers:

    gdb
    strace-like tools
    crash/debug tools


Flow:

get_fpregs(buf, task)
      |
      +--> init_fpu(task)
      |
      +--> copy task->thread.i387.fxsave to user buffer


===============================================================================
set_fpregs()
===============================================================================

Purpose:

    ptrace writes task FPU registers.


Flow:

set_fpregs(task, buf)
      |
      +--> copy user buffer into task->thread.i387.fxsave


Used by debuggers to modify FPU/SSE state.


===============================================================================
dump_fpu()
===============================================================================

Purpose:

    Save current task FPU state for core dump.


Flow:

dump_fpu(regs, fpu)
      |
      +--> if task never used math:
      |        |
      |        +--> return 0
      |
      +--> unlazy_fpu(current)
      |
      +--> copy fxsave state into core dump buffer
      |
      +--> return 1


unlazy_fpu()
------------

If FPU state is still live in CPU registers, save it into task_struct.


===============================================================================
dump_task_fpu()
===============================================================================

Purpose:

    Save arbitrary task's FPU state for core dump/debugging.


Flow:

dump_task_fpu(task, fpu)
      |
      +--> fpvalid = task used math?
      |
      +--> if valid:
              |
              +--> if task is current:
              |        |
              |        +--> unlazy_fpu(task)
              |
              +--> copy fxsave state
      |
      +--> return fpvalid

===============================================================================

===============================================================================
RELATION TO entry.S
===============================================================================

entry.S has exception entry:

    device_not_available:
        zeroentry math_state_restore


This handles #NM exception.

Flow:

Task executes FPU instruction while CR0.TS=1
      |
      v
#NM Device Not Available
      |
      v
entry.S device_not_available
      |
      v
math_state_restore()
      |
      v
restore/init FPU state


i387.c provides the saved state and initialization logic used by that path.


===============================================================================
KEY IDEA
===============================================================================

This file manages the expensive floating-point/SSE state lazily.

Instead of saving/restoring FPU state on every context switch, Linux tracks
whether a task actually used FPU.

When needed, it saves/restores FPU state through FXSAVE/FXRSTOR-compatible
storage in:

    task_struct.thread.i387.fxsave


It also exposes that state correctly to:

    - signal handlers
    - ptrace/debuggers
    - core dumps


In simple words:

    i387.c protects each process's floating-point/SSE register state.
