============================================================
PTRACE vs INT3
The Complete Debugging Architecture on x86-64
============================================================

GOAL
------------------------------------------------------------

Many kernel engineers initially think:

    ptrace == INT3

This is NOT true.

The correct relationship is:

    ptrace is a control API

while

    INT3 is one possible debugging mechanism

used by tools that happen to use ptrace.

This file explains:

    What ptrace actually is
    What INT3 actually is
    How GDB works
    How strace works
    How single-step works
    How hardware breakpoints work
    Why ptrace does NOT inherently use INT3

============================================================
CHAPTER 1
WHAT IS PTRACE?
============================================================

ptrace means:

    Process Trace

It is a Linux kernel API.

============================================================

Debugger Process
        |
        |
        v
    ptrace()
        |
        v
     Kernel
        |
        v
Target Process

============================================================

Think of ptrace as:

    "Remote control for another process"

============================================================

A debugger can ask:

    Read memory

    Write memory

    Read registers

    Change RIP

    Continue execution

    Stop execution

    Single step

    Trace syscalls

============================================================

Notice:

None of these require INT3.

============================================================
CHAPTER 2
WHAT IS INT3?
============================================================

INT3 is a CPU instruction.

Opcode:

    0xCC

============================================================

Assembly:

    int3

============================================================

When CPU executes it:

============================================================

INT3
   |
   v
#BP
(Breakpoint Exception)
   |
   v
Kernel Exception Handler
   |
   v
SIGTRAP

============================================================

INT3 is only:

    a software breakpoint instruction

============================================================

It is NOT ptrace.

============================================================
CHAPTER 3

============================================================

Many people see:

============================================================

 v

 |
 v

============================================================

    ptrace uses INT3

============================================================

Reality:

============================================================

ptrace

 +--> can use INT3
 |
 +--> can use TF
 |
 +--> can use DR0-DR7
 |
 +--> can use syscall tracing

============================================================

INT3 is only one possible tool.

============================================================

    ...

============================================================

============================================================

============================================================

============================================================

============================================================

    cc

============================================================

============================================================

#DB

SIGTRAP

============================================================

      |

MENTAL MODEL
============================================================

ptrace
 |
 +------------------------------+
 |                              |
 |                              |
 v                              v

CONTROL API                DEBUG EVENTS

                                |
                                +--> INT3 -> #BP
                                |
                                +--> TF -> #DB
                                |
                                +--> DR0 -> #DB
                                |
                                +--> Syscall Stops
                                |

============================================================
ONE-LINE SUMMARY
============================================================

ptrace itself does not use INT3. ptrace is a process-control API
that allows debuggers to inspect and manipulate another task.
Tools like GDB may choose to use INT3 for software breakpoints,
the Trap Flag (TF) for single-stepping, DR0-DR7 for hardware
breakpoints, or syscall-tracing hooks, all accessed through the
ptrace interface.
