```text
===============================================================================
AMD K8 NORTHBRIDGE / GART SUPPORT
File: arch/x86_64/kernel/k8.c
===============================================================================

PURPOSE
=======

This file provides shared helper code for AMD K8 northbridges.

It mainly supports:

    1. finding AMD K8 northbridge PCI devices
    2. caching their pci_dev pointers
    3. detecting K8 northbridges during early boot
    4. flushing GART/IOMMU translations


===============================================================================
BACKGROUND: WHAT IS A K8 NORTHBRIDGE?
===============================================================================

AMD K8 systems have northbridge functionality integrated with the CPU.

The northbridge controls important system features such as:

    - memory controller
    - HyperTransport links
    - GART/IOMMU aperture
    - DMA remapping behavior


Linux needs to find these northbridge PCI function devices because some
hardware control registers live there.


===============================================================================
BACKGROUND: WHAT IS GART?
===============================================================================

GART = Graphics Address Remapping Table

Historically used for AGP graphics, but also used as an IOMMU-like DMA
remapping mechanism on AMD K8.

Device sees:

    DMA address inside aperture

Hardware translates it to:

    real physical memory


Flow:

Device DMA
    |
    v
GART aperture
    |
    v
GART translation
    |
    v
Real RAM page


When GART mappings change, hardware translation caches must be flushed.


===============================================================================
IMPORTANT GLOBALS
===============================================================================

num_k8_northbridges
-------------------

Number of detected AMD K8 northbridges.


k8_northbridges
---------------

Array of struct pci_dev pointers.

Each entry points to one K8 northbridge PCI function.


flush_words
-----------

Saved values from PCI config register 0x9c.

Used when requesting GART flush.


k8_nb_ids
----------

PCI IDs recognized as AMD K8 northbridge devices:

    AMD vendor + device 0x1103
    AMD vendor + device 0x1203


===============================================================================
PCI DEVICE ID TABLE
===============================================================================

Code:

    struct pci_device_id k8_nb_ids[] = {
        { PCI_DEVICE(PCI_VENDOR_ID_AMD, 0x1103) },
        { PCI_DEVICE(PCI_VENDOR_ID_AMD, 0x1203) },
        {}
    };


Meaning:

    These PCI devices are treated as K8 northbridge devices.


===============================================================================
next_k8_northbridge()
===============================================================================

Purpose:

    Find next PCI device matching k8_nb_ids.


Flow:

next_k8_northbridge(dev)
      |
      +--> pci_get_device(any vendor, any device, dev)
      |
      +--> if no device:
      |       |
      |       +--> return NULL
      |
      +--> check pci_match_id(k8_nb_ids)
      |
      +--> if match:
              |
              +--> return dev


This walks the PCI device list.


===============================================================================
cache_k8_northbridges()
===============================================================================

Purpose:

    Discover and cache all K8 northbridges.


Why cache?

Other code needs quick access to these PCI devices, especially GART/IOMMU
code.


Flow:

cache_k8_northbridges()
      |
      +--> if already cached:
      |       |
      |       +--> return 0
      |
      +--> scan PCI devices and count K8 northbridges
      |
      +--> allocate k8_northbridges array
      |
      +--> allocate flush_words array
      |
      +--> scan again and store pci_dev pointers
      |
      +--> read config register 0x9c into flush_words
      |
      +--> terminate array with NULL
      |
      v
return 0


===============================================================================
CACHE LAYOUT
===============================================================================

Example system with 2 K8 northbridges:

k8_northbridges
    |
    +--> [0] pci_dev for northbridge 0
    +--> [1] pci_dev for northbridge 1
    +--> [2] NULL


flush_words
    |
    +--> [0] saved config 0x9c value for NB0
    +--> [1] saved config 0x9c value for NB1


===============================================================================
EARLY DETECTION
===============================================================================

Function:

    early_is_k8_nb(u32 device)


Purpose:

    Check if raw PCI vendor/device value belongs to K8 northbridge.


Used before normal PCI subsystem may be available.


Input:

    device = raw PCI config dword

Format:

    low 16 bits  = vendor ID
    high 16 bits = device ID


Flow:

early_is_k8_nb(device)
      |
      +--> vendor = device & 0xffff
      |
      +--> device_id = device >> 16
      |
      +--> compare with k8_nb_ids[]
      |
      +--> return 1 if match
      |
      +--> otherwise return 0


Connection:

    aperture.c uses this during early IOMMU aperture setup.


===============================================================================
GART FLUSH
===============================================================================

Function:

    k8_flush_garts()


Purpose:

    Flush GART/IOMMU translation caches on all K8 northbridges.


Why needed?

When kernel changes GART mappings, hardware may still have old cached
translations.

Need to force hardware to reload them.


===============================================================================
k8_flush_garts() FLOW
===============================================================================

k8_flush_garts()
      |
      +--> take gart_lock
      |
      +--> for each K8 northbridge:
      |       |
      |       +--> write config register 0x9c with flush bit set
      |
      +--> for each K8 northbridge:
      |       |
      |       +--> poll config register 0x9c
      |       +--> wait until flush bit clears
      |
      +--> release gart_lock
      |
      +--> if no northbridge flushed:
              |
              +--> print "nothing to flush?"


===============================================================================
REGISTER 0x9c
===============================================================================

This code treats PCI config register 0x9c as the GART flush control register.


Flush request:

    pci_write_config_dword(dev, 0x9c, flush_words[i] | 1)


Wait complete:

    pci_read_config_dword(dev, 0x9c, &w)

    while (w & 1)
        cpu_relax()


Meaning:

    bit 0 set   = flush pending/requested
    bit 0 clear = flush complete


===============================================================================
WHY SERIALIZE WITH gart_lock?
===============================================================================

Comment says:

    Avoid races between AGP and IOMMU.

Two users may request GART flush:

    AGP driver
    IOMMU code


If both write flush register at same time, hardware might lose one request.

So Linux serializes flushes:

    spin_lock_irqsave(&gart_lock, flags)


===============================================================================
GART FLUSH DIAGRAM
===============================================================================

Before:

    GART table changed
          |
          v
    hardware may still use old cached translation


Flush:

    write flush bit to every K8 northbridge
          |
          v
    hardware invalidates cached GART entries


After:

    device DMA uses new GART mappings


===============================================================================
RELATION TO aperture.c
===============================================================================

aperture.c:

    finds or creates GART aperture

k8.c:

    finds K8 northbridges
    flushes GART translations


Flow:

aperture.c
    |
    +--> early_is_k8_nb()
    |
    +--> configure aperture base/size

GART/IOMMU code
    |
    +--> cache_k8_northbridges()
    |
    +--> k8_flush_garts()


===============================================================================
RELATION TO IOMMU
===============================================================================

When IOMMU mappings change:

    update GART table
        |
        v
    k8_flush_garts()
        |
        v
    hardware translation cache invalidated


Without flush:

    device may DMA using stale translation

Possible result:

    memory corruption


===============================================================================
COMPLETE FLOW
===============================================================================

Boot / PCI discovery
      |
      v
cache_k8_northbridges()
      |
      +--> find AMD K8 northbridge PCI devices
      |
      +--> save pci_dev pointers
      |
      +--> save flush register values
      |
      v
GART/IOMMU code changes mapping
      |
      v
k8_flush_garts()
      |
      +--> set flush bit on all northbridges
      |
      +--> wait until hardware clears flush bit
      |
      v
new DMA translations visible


===============================================================================
KEY IDEA
===============================================================================

This file is small but important.

It is shared infrastructure for AMD K8 northbridge handling.

Its most important job is:

    make sure GART/IOMMU translation changes become visible to hardware

by flushing all K8 northbridges.

Without this, devices could continue DMA through stale mappings.
===============================================================================
```
