===============================================================================
E820 MEMORY MAP MANAGEMENT
File: arch/x86_64/kernel/e820.c
===============================================================================

PURPOSE
=======

This file is the foundation of x86_64 memory management during early boot.

Its job is to answer:

    What physical memory exists?
    Which regions are RAM?
    Which regions are reserved?
    Which regions contain ACPI tables?
    Which regions must never be touched?

Before bootmem, buddy allocator, NUMA, or page allocator exist,
this file is responsible for understanding physical memory layout.


===============================================================================
BACKGROUND : WHAT IS E820?
===============================================================================

E820 comes from BIOS INT 15h, E820 service.

Firmware provides a memory map:

Example:

+----------------------+----------------------+
| Physical Range       | Type                 |
+----------------------+----------------------+
| 0x00000000-0x0009FFFF| RAM                  |
| 0x000A0000-0x000FFFFF| Reserved             |
| 0x00100000-0x7FFFFFFF| RAM                  |
| 0x80000000-0x80FFFFFF| ACPI                 |
| 0x81000000-0xFFFFFFFF| Reserved             |
+----------------------+----------------------+

Linux receives this map during boot.

}


===============================================================================
E820 TYPES
===============================================================================

E820_RAM
---------
Usable memory.

Kernel may allocate pages.


E820_RESERVED
-------------
Never touch.

May contain:

    device memory
    firmware structures
    chipset windows


E820_ACPI
---------
ACPI tables.


E820_NVS
--------
ACPI Non Volatile Storage.

Must survive suspend/resume.


===============================================================================
IMPORTANT GLOBALS
===============================================================================

end_pfn
--------

Highest usable RAM PFN.

Only RAM pages.


end_pfn_map
-----------

Highest PFN appearing anywhere in E820.

Includes:

    RAM
    ACPI
    MMIO
    Reserved regions

Why?

Direct map extends further than RAM.


Example:

RAM ends at:

    PFN 1,000,000

ACPI/MMIO ends at:

    PFN 1,100,000

Then:

    end_pfn      = 1,000,000
    end_pfn_map  = 1,100,000


===============================================================================
BAD ADDRESS CHECK
===============================================================================

Function:

    bad_addr()

Purpose:

Find physical regions early boot must never overwrite.


Checks:

1. Low memory SMP startup area

       below 0x8000

2. Kernel page tables

       table_start -> table_end

3. Initrd

4. Kernel image

       _text -> _end

5. EBDA

       BIOS data area


Diagram:

Physical Memory

0x00000000
     |
     +--> Reserved SMP startup
     |
     +--> EBDA
     |
     +--> Kernel Image
     |
     +--> Initrd
     |
     +--> Page Tables
     |
     +--> Free


If allocation overlaps any of these:

    move allocation forward

    e820_any_mapped(start,end,type)

    Does ANY part of this range overlap an E820 region?


Example:

Range:

    100MB-200MB

Check:

    Any E820_RAM there?

Returns:

    YES / NO

Function:

    e820_all_mapped(start,end,type)

Question:

    Is ENTIRE range covered by E820 entries?

Example:

    100MB-200MB

Covered completely by RAM?

Returns:

    YES / NO

===============================================================================
WHY SANITIZE E820?
===============================================================================

Many BIOSes are buggy.

Example:

Entry 1:

    RAM
    0MB -> 1GB

Entry 2:

    Reserved
    500MB -> 700MB

Overlap!

Kernel must resolve it.


===============================================================================
sanitize_e820_map()
===============================================================================

Most complicated function in file.

Purpose:

Convert overlapping BIOS map into clean non-overlapping map.


Input:

RAM:
0 ----- 1000

Reserved:
500 ---- 700


BIOS gives:

RAM      [0----------------1000]
Reserved      [500----700]


Kernel converts to:

RAM       [0----500]
Reserved       [500----700]
RAM                    [700----1000]


Algorithm:

1. Gather all start/end points.

2. Sort change points.

3. Walk left-to-right.

4. Track overlapping entries.

5. Choose highest priority type.

Rule:

Higher type wins.

Example:

RAM type=1
Reserved type=2

Reserved wins.


===============================================================================
SANITIZE FLOW
===============================================================================

Original BIOS Map
       |
       v
Collect start/end addresses
       |
       v
Sort all change points
       |
       v
Walk address space
       |
       v
Determine active overlaps
       |
       v
Choose strongest type
       |
       v
Generate new clean map

===============================================================================
PCI MMIO GAP SEARCH
===============================================================================

Function:

    e820_setup_gap()

Purpose:

Find largest hole below 4GB.

Why?

PCI MMIO BARs need address space.


Example Memory Layout:

0GB ---------------- 2GB RAM

2GB ---------------- 2.5GB HOLE

2.5GB -------------- 4GB RAM


Largest gap:

    2GB -> 2.5GB


Use:

    PCI MMIO allocation


Result:

pci_mem_start = gap location


===============================================================================

===============================================================================

      |
      v
Find largest unused hole
      |
      v
Align hole
      |
      v
pci_mem_start
      |
      v
PCI resource allocator uses it
